terraform-gcp-composer Architecture Document

Cloud Composer Module

Executive Summary

A production-ready Terraform module for deploying managed Apache Airflow environments on Google Cloud Composer 2/3. Provides configurable software settings (Airflow overrides, environment variables, PyPI packages), private networking with VPC peering or Private Service Connect, fine-grained workload configuration for scheduler, web server, workers, and triggerer components, CMEK encryption, maintenance windows with recurrence rules, web server IP access controls, master authorized networks, Cloud Data Lineage integration, and HIGH_RESILIENCE mode for multi-zone production deployments.

Component Breakdown

google_composer_environment.this

Core Composer environment resource with 60-minute create/update timeouts and 30-minute delete timeout. Configures environment size (SMALL/MEDIUM/LARGE), resilience mode (HIGH_RESILIENCE for multi-zone), and comprehensive nested configurations.

Software Config

Airflow image version, config overrides (section-key pairs), environment variables, PyPI package installation with version specs, Python version, and Cloud Data Lineage integration.

Node Config

GKE cluster configuration with VPC network, subnetwork, service account, network tags, and IP allocation policy for pod/service CIDR ranges.

Workloads Config (Composer 2)

Independent CPU, memory, and storage allocation for scheduler (1-3 instances), web server, workers (auto-scaling min/max), and triggerer components.

Private Environment Config

Private IP with configurable CIDR blocks for GKE master, Cloud SQL, web server, and Composer tenant network. Supports VPC_PEERING and PRIVATE_SERVICE_CONNECT connection types.

Data Flow

  • DAG Deployment: DAGs are uploaded to the Cloud Storage DAG folder (dag_gcs_prefix), synced to the Airflow scheduler.
  • Task Scheduling: Scheduler (1-3 instances) parses DAGs and schedules tasks. Workers auto-scale to process task queue.
  • Web UI: Airflow web server provides DAG visualization, task logs, and manual triggers. Access controlled by web server ACLs.
  • Triggerer: Handles deferrable operators, enabling efficient long-running task patterns without blocking worker slots.
  • External Access: Workers connect to external data sources through VPC networking (BigQuery, Cloud SQL, GCS, APIs).

Industry Adaptation

  • Data Engineering: Large environment with multiple workers for ETL pipelines, PyPI packages for custom operators (dbt, Great Expectations), scheduled data quality checks.
  • Financial Services: Private IP environment, CMEK encryption, restricted web server ACLs, Cloud Data Lineage for regulatory audit trails.
  • Machine Learning: Custom PyPI packages (scikit-learn, pandas, TensorFlow), triggerer for long-running training jobs, GCS-based model artifact DAGs.
  • Healthcare: HIGH_RESILIENCE mode for critical pipeline availability, private networking, master authorized networks, CMEK for PHI-adjacent workflows.

Production Readiness Checklist

  • Enable private IP environment with VPC peering or PSC
  • Configure CMEK encryption for environment data
  • Set resilience_mode = "HIGH_RESILIENCE" for multi-zone deployment
  • Use ENVIRONMENT_SIZE_MEDIUM or LARGE for production workloads
  • Configure maintenance windows during off-peak hours
  • Set web server ACLs to restrict Airflow UI access
  • Configure master authorized networks for GKE access
  • Assign dedicated service account with least-privilege IAM
  • Set scheduler count to 2+ for redundancy
  • Configure worker auto-scaling (min_count >= 1 for production)
  • Pin Airflow image version for reproducible deployments
  • Apply labels for cost tracking and resource organization

Deployment

module "composer" {
  source = "github.com/kogunlowo123/terraform-gcp-composer"

  project_id       = "my-project"
  region           = "us-central1"
  name             = "prod-airflow"
  environment_size = "ENVIRONMENT_SIZE_MEDIUM"
  resilience_mode  = "HIGH_RESILIENCE"
  image_version    = "composer-2.6.6-airflow-2.7.3"

  network         = "projects/my-project/global/networks/default"
  subnetwork      = "projects/my-project/regions/us-central1/subnetworks/default"
  service_account = "composer-sa@my-project.iam.gserviceaccount.com"

  enable_private_environment = true
  private_environment_config = {
    enable_private_endpoint    = true
    master_ipv4_cidr_block     = "172.16.0.0/28"
    cloud_sql_ipv4_cidr_block  = "10.0.0.0/12"
  }

  scheduler = { cpu = 2, memory_gb = 4, count = 2 }
  worker    = { cpu = 2, memory_gb = 4, min_count = 2, max_count = 6 }

  pypi_packages = {
    "apache-airflow-providers-slack" = ">=7.0.0"
    "pandas"                         = ">=2.0.0"
  }

  kms_key_name = "projects/my-project/locations/us-central1/keyRings/ring/cryptoKeys/key"

  labels = { team = "data-engineering", env = "production" }
}
